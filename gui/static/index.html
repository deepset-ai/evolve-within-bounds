How the agent evolved

An AI optimizer rewrote a deliberately weak security agent seven times. Each version was tested on pairs of small code repositories: one with a vulnerability we planted, and its fixed twin. A pair counts when the agent finds the planted vulnerability and leaves the fixed code alone.

Watch it improve

One round of the loop, from a weak agent to an improvement a person approves: about 3 to 5 minutes.

  1. The taskA benchmark of small code repositories, each with a planted vulnerability and a fixed twin.
  2. Where it startsThe starting agent's result on one training pair, and where it went wrong.
  3. The optimizer at workAn AI optimizer reads what the agent did and rewrites its instructions.
  4. What changedThe change, line by line, like a code review.
  5. Testing the changeThe new version scans the same pair again, inside a sandbox.
  6. A person decidesOnly an improvement is offered, and only a person can deploy it.
  7. The resultThe deployed agent scans a repository it has never seen.

Spot the vulnerability

      
Pairs of real C functions from PrimeVul:
        a function as it was before a public security fix, and the patched version. The agent judges each function on
        its own, and a pair only counts when it calls the vulnerable one vulnerable and the patched one safe. On 100
        held-out pairs the evolved agent gets 21 right; the agent it started from got 16. The pairs here were picked for
        short functions, half of them ones it got right, with its verdicts from that run.
